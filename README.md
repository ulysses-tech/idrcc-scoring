# IDCC 2026 · DCC Scoring System

심판 채점 및 HQ 집계 웹앱 (React + Vite + Tailwind + Firebase Realtime Database)

## 배포
- **GitHub Pages**: `main` 브랜치에 커밋하면 `.github/workflows/deploy.yml`이 자동으로 빌드·배포합니다.
  최초 1회 **Settings → Pages → Source = GitHub Actions** 로 설정해야 합니다.
- **Netlify(선택)**: 이 저장소를 Netlify에 연결하면 `netlify.toml` 설정(빌드 `npm run build`, 게시 폴더 `dist`)으로 자동 배포됩니다.

## 수정할 파일
- 앱 코드: `src/App.jsx` (비밀번호·카테고리·점수 규칙은 파일 상단 상수)
- 아이콘: `public/` 폴더

## PC에서 직접 실행(개발자용)
```
npm install
npm run dev
```

## 참가자 명단 (엑셀 연동)

1. **HQ Admin → 참가자 명단 → 양식 받기**로 빈 엑셀 양식을 내려받습니다.
2. 양식에 `순서 | 참가번호 | 이름 | 부문 | 국가 | 소속 | 학년 | 성별 | 조` 를 채웁니다.
   - 제목 줄 이름만 맞으면 칸 순서는 자유입니다. (`순번`, `배번`, `성명`, `참가부문`, `학교` 등 비슷한 이름도 인식)
   - `부문`은 `초등`·`중등`·`고등`·`일반`(또는 Elementary/Middle/High/General)으로 적으면 Category가 자동 선택됩니다.
   - `순서` 칸이 없으면 엑셀의 줄 순서대로 진행합니다. `조`는 심판이 여러 명일 때 코스를 나누는 데 씁니다(선택).
3. **엑셀 명단 불러오기** → 미리보기 확인 → **저장**. 모든 심판 화면에 즉시 나타납니다. 명단을 다시 불러와도 채점 기록은 유지됩니다.

**심판 화면(Judge Console)**
- 1번 **Judge Name**을 먼저 입력합니다(기기에 기억됨). 조가 있으면 담당 조를 고릅니다.
- **다음 순서** 참가자가 크게 보입니다. **이 참가자 채점**을 누르면 번호·이름·부문이 자동으로 채워집니다.
- '다음 순서'는 심판이 고른 **Trial(1st/2nd)** 기준으로 계산합니다. 2차 시기를 시작할 때는 Trial을 `2nd`로 바꾸면 처음 순서부터 다시 나옵니다.
- 선택한 참가자는 다른 심판 화면에 **'채점 중 · 심판 이름'** 으로 표시되어 자동으로 건너뜁니다. 제출하면 '완료'로 바뀝니다.
- 순서가 바뀐 참가자는 **명단에서 직접 찾기**에서 번호나 이름으로 찾습니다. 명단에 없는 참가자는 번호·이름을 직접 입력하면 됩니다.

## HQ: 서명 보기 · 개별 삭제

- 결과표의 **Signature** 칸에 학생 서명이 작게 보이고, 누르면 크게 볼 수 있습니다. 엑셀에는 서명 여부(Y/N)가 저장됩니다.
- 각 줄 오른쪽 **휴지통** 버튼으로 기록 1건(서명 포함)을 삭제합니다. 연필 버튼은 수정입니다.

## Firebase 규칙 (명단 기능에 필요)

명단은 `dcc_meta`에 저장됩니다. Firebase 콘솔 → Realtime Database → **규칙**에서 기존 내용은 그대로 두고 `"rules": {` 바로 아래에 다음을 추가한 뒤 **게시**하세요.

```json
"dcc_meta": {
  ".read": true,
  ".write": true
},
```

## 라운드 진행 방식 (심판 화면)

**진행 방식 선택** (심판 화면 1번 Participant 칸, 기기마다 기억됨)
- **라운드별 진행 (전원 1R → 2R)**: 확정하면 명단의 다음 참가자로 넘어갑니다. 2라운드를 시작할 때 Round를 `2 라운드`로 바꿉니다.
- **참가자별 연속 (1R → 바로 2R)**: 1라운드를 확정하면 같은 참가자의 2라운드로 바로 넘어갑니다(코딩 점수는 이어받으며 수정 가능). 2라운드까지 확정하면 다음 참가자의 1라운드로 넘어갑니다. 명단의 '다음 순서'는 두 라운드를 모두 마치지 않은 첫 참가자이며, 1라운드만 마친 참가자는 2라운드부터 이어서 시작합니다.

참가자 1명은 **2라운드 × 라운드당 2회 비행 = 총 4회** 비행합니다. 라운드마다 3분 안에 2회를 연속으로 비행하므로, 심판 화면은 라운드 단위로 진행합니다.

1. **참가자 선택**(명단의 '이 참가자 채점') → **Round**(1 라운드 / 2 라운드) 확인 → **Coding** 점수 입력 → 준비 알림 **확인**
2. **1차 비행** — 심판 신호와 함께 하단 **1차 START**
   - 비행 중 성공한 임무 단계를 **각각** 누릅니다. 누른 단계만 점수가 들어가고, 다시 누르면 취소됩니다.
   - 착륙은 색깔별 **+** 버튼
   - 비행이 끝나면 **1차 STOP** → **1차 기록이 자동 저장되어 HQ에 바로 표시**됩니다.
3. **2차 비행** — 참가자가 신호 없이 출발하므로, STOP 직후 깜빡이는 **2차 START**를 바로 누릅니다. 끝나면 **2차 STOP**.
   - 2차 비행을 하지 않았다면 **2차 비행 안 함**
4. **학생 확인·서명** — 1·2차 기록 요약(★ 최고 기록 표시)을 학생이 확인하고 서명 → **서명 완료 · 라운드 확정**. 이때 2차 기록이 HQ에 올라가고 다음 참가자로 넘어갑니다.

- STOP을 잘못 눌렀다면 하단 **○차 계속**으로 처음 시작 시각부터 이어서 측정합니다.
- 저장된 1차 기록은 서명 전까지 단계·착륙·시간을 고치면 HQ 기록도 자동으로 고쳐집니다.
- 진행 상태는 기기에 저장되어, 새로고침하거나 HQ에 다녀와도 이어서 진행됩니다.
- 1차만 저장되고 중단된 참가자를 다시 고르면 2차 비행부터 이어서 진행합니다.
- 서명은 라운드마다 1회(총 2회)이며, 같은 라운드의 1·2차 기록이 함께 사용합니다.

## HQ · 최종 순위 · 엑셀

- HQ는 기본으로 **최종 순위 (4회 중 최고)**를 보여 줍니다. 동점이면 시간이 짧은 기록이 앞섭니다. **전체 비행 기록**으로 4회 기록을 모두 볼 수 있습니다.
- **Export Excel** 시트 구성: `Final (Best of 4)` (참가자별 4회 점수·시간 + 최종 최고 기록), `All Flights` (모든 비행 기록), 부문별 최종 순위 시트.
